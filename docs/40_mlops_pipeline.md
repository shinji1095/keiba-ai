# MLOps Pipeline（収集→学習→評価→登録→配布）

## 1. 目的
- 学習を定期実行し、再現性・監査性を維持したままモデルを更新する
- データ変化やモデル劣化を検知し、ロールバック可能な運用を実現する

## 2. パイプライン全体像（一次案）
1. Ingest: DB から学習対象期間を抽出（スナップショット・結果を結合）
2. Validate: Great Expectations 等でデータ品質チェック
3. Feature: 特徴量生成（worker で分散）
4. Train:
   - 分類モデル学習
   - 強化学習（環境は“過去レースの再現”として定義）
5. Evaluate:
   - 予測性能（分類指標）
   - 収益指標（バックテスト）
   - ドリフト（分布変化）
6. Register: MLflow に実験・モデルを登録（メタデータ：データ版、コード版、パラメータ）
7. Promote/Deploy: “候補”→“本番”の昇格ルールに基づき反映（手動承認 or 自動）

## 3. スケジュール（例）
- daily: 前日分のデータ取り込み・検証・軽量学習
- weekly: フルリトレーニング + ハイパラ探索（必要なら）
- on-demand: サイト変更や障害復旧後の再学習

## 4. 再現性の要件
- データ版：DVC（またはDBスナップショット）で追跡
- コード版：Git commit hash
- 実験：MLflow run id
- モデル：MLflow registry version + 生成時刻
- これらを “1つのレポート” として保存し、後で同じ結果を再現できること

## 5. 昇格（Promotion）ルール（暫定）
- 最低限：直近バックテストでベースライン以上
- データ品質チェックを通過
- 重大な欠損が無い
- 重大なモデル劣化が無い（過学習、ドリフト）

## 6. アラート（必須）
- 学習失敗（連続N回）
- データ品質失敗
- モデル性能劣化
