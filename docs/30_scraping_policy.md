# Scraping Policy（負荷抑制・取得タイミング・障害設計）

このドキュメントは「スクレイピングは必須」「負荷をかけない頻度を遵守」を実装・運用に落とすためのルール集である。
コードの設定値ではなく **運用契約** として扱う。

## 1. 基本原則
- 対象サイトの利用規約・robots.txt を確認し、遵守する
- 同時接続数を絞り、AutoThrottle を有効化する
- リトライは指数バックオフ + ジッターを必須にする
- HTML構造変化は “異常” として検知し、アラート対象とする

## 2. 取得対象（一次案）
- レース一覧（開催日/競馬場/レース番号/発走時刻）
- 代表オッズスナップショット（最終、T-1m、T-5m）
- （将来）馬場、出走表、結果/払戻

## 3. 取得タイミング（一次案）
- tick の定義を固定：
  - T-5m: 発走予定時刻の 5 分前を目標に取得
  - T-1m: 発走予定時刻の 1 分前を目標に取得
  - Final: 締切/確定に最も近い取得（“最終”の定義は対象サイト仕様に従う）
- “目標時刻に取得できない”場合の扱い：
  - 遅延取得は許容するが captured_at を必ず保存し、tick は “意図したラベル” として残す
  - 遅延閾値を超えた場合は tick を付与しない（欠損扱い）

## 4. 負荷抑制（推奨デフォルト）
- CONCURRENT_REQUESTS: 2
- DOWNLOAD_DELAY: 1.0s
- AUTOTHROTTLE_TARGET_CONCURRENCY: 1.0
- AUTOTHROTTLE_MAX_DELAY: 10.0s
※上記は “起点” であり、実際は対象サイトの許容に合わせて調整する。

## 5. 障害設計（必須）
- 取得失敗（HTTP/timeout）: リトライ → 失敗ログ → アラート
- パーサ崩壊（DOM差分・必須要素欠落）: 即時アラート + HTMLフィクスチャ保存
- 取得停止（一定時間0件）: 生存監視（heartbeat）で検知

## 6. HTMLフィクスチャ運用（TDDの基盤）
- 代表ページの HTML を定期的に保存（差分検知）
- パーサはフィクスチャを入力にユニットテスト化し、サイト変更で即座にCIが落ちるようにする
- フィクスチャの保存先や保持期間は容量と相談し、運用で合意する

## 7. 変更管理
- 取得頻度・同時接続数・ユーザーエージェント変更は、PRでレビュー必須
- 破壊的変更は Decision Log に記録する
